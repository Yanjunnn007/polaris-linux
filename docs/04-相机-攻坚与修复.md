# 小米 MIX 2S (polaris) postmarketOS 第四阶段成果报告：索尼 IMX363 后置主摄 4032×3024 硬件出图与录像完全打通

> **设备**：小米 MIX 2S (`polaris`)，SoC 高通骁龙 845 (`SDM845`)，PMIC PM8998 + PMI8998  
> **系统**：postmarketOS edge / Phosh / openrc / 内核 `7.1.0-rc1-sdm845` (`r24` / `#25`)  
> **完成日期**：2026-10-13  
> **实测验证**：**4032×3024 全分辨率单帧 15.24MB 稳定捕获、拍照全彩成像、视频录制流畅、AK7372 VCM 音圈马达硬件调焦支持（0~4095 步进）**

---

## 一、 阶段里程碑概览

在经历了第一阶段（屏幕/GPU/无线网络）、第二阶段（USB-SSH/音频与冻结诊断）以及第三阶段（Type-C OTG 双角色自动盲插与 5V 升压供电）之后，摄像头子系统成为了 MIX 2S 移植主线 Linux 最后的“深水区”。

在社区历史上，高通 SDM845 主线相机由于依赖私有 Spectra 280 硬件 ISP 固件微码，长期处于“Broken / 搁置”状态。Poco F1 的旧分支补丁在 MIX 2S 上甚至连芯片都无法探测识别。

在第四阶段攻坚中，我们**彻底攻克了物理探测、供电拓扑、CAMSS RDI 链路、软硬解耦 ISP 以及音圈对焦马达控制**，实现了：
1. **索尼 IMX363 后置主摄 100% 物理识别与硬件直驱**（芯片 ID `0x0363`，真实 I2C 从机地址 `0x1a`）；
2. **全分辨率 4032×3024 10-bit Packed Bayer（`pBAA`）RAW 帧硬件 DMA 直写**（单帧精确 15,240,960 字节，零丢帧、零溢出）；
3. **软硬解耦架构**：通过 V4L2 寄存器直通索尼片上物理电子快门与模拟增益运放（PGA），配合轻量化软件 ISP，拍照全彩出图，视频流流畅播放；
4. **旭化成 AK7372 12-bit VCM 音圈对焦马达驱动与硬件控制**（I2C 地址 `0x0c`，2.8V 独立供电，0~4095 DAC 步进，从微距到无限远平滑调焦）。

## 二、 核心攻坚战报与技术破局

```
[ 索尼 IMX363 硅片感光阵列 ]
        ↓ (4-Lane MIPI CSI-2 差分信号, 636MHz DDR)
[ 高通 SDM845 CSIPHY0 物理层接收 ]
        ↓
[ CSID0 接口解码器 (解析 CSI-2 数据包头) ]
        ↓ (直接旁路绕开高通闭源硬件 ISP！)
[ VFE0 RDI0 (直接内存访问 DMA 引擎) ]
        ↓ (Linux 内核环形缓冲区队列)
[ /dev/video0 V4L2 userspace 映射 ]
```

### 1. 真实 I2C 从机地址破译（0x10 $\rightarrow$ 0x1a）
- **现象**：Poco F1 社区驱动假设地址为 `0x10`，在 MIX 2S 上读芯片 ID 永远返回 `-EIO`。
- **逆向破局**：解压 MIUI 官方底包 `vendor.raw.img`，反编译高通相机 Chromatix 二进制配置文件 `com.qti.sensormodule.imx363.bin`。在偏移 `0x1efdc` 查得 Polaris 真实 8-bit 地址为 `0x34` $\rightarrow$ **7-bit 地址为 `0x1a`**，芯片 ID 寄存器 `0x0016`。
- **验证**：修改驱动与 DTS 后，开机内核日志一次识别通过：
  ```text
  [ 6.800279] imx363 16-001a: Starting IMX363 identification on addr 0x1a...
  [ 6.800411] imx363 16-001a: Found IMX363 chip id 0x0363 on addr 0x1a (attempt 0)!
  [ 6.800429] imx363: pixel_rate: 508800000
  ```

### 2. 供电树拓扑与时序编排
- **电源轨绑定**：
  - `cam0_dvdd` (数字核心 1.05V): PM8998 GPIO 11
  - `cam0_avdd` (模拟感光 2.80V): TLMM GPIO 87
  - `cam_iovdd` (接口电平 1.80V): TLMM GPIO 21
  - `cam0_custom` (自定义/马达供电): TLMM GPIO 102
- **上电时序控制**：保持 GPIO 80 低电平复位 $\rightarrow$ 开启四路供电 $\rightarrow$ 延时 2ms $\rightarrow$ 注入 24MHz CAMCC MCLK 时钟 $\rightarrow$ 延时 2ms $\rightarrow$ 释放复位高电平 $\rightarrow$ 延时 5ms 稳定。

### 3. CAMSS 格式断管与 RDI 直通
- **现象**：连接 CSIPHY0 $\rightarrow$ CSID0 $\rightarrow$ VFE0 RDI0 $\rightarrow$ `/dev/video0` 后，抓帧抛出 `-EPIPE` (Broken pipe)。
- **破局**：CAMSS CSID 输出为 `MEDIA_BUS_FMT_SBGGR10_1X10`，V4L2 必须匹配紧凑打包的 MIPI RAW10 格式 `pBAA` (`V4L2_PIX_FMT_SBGGR10P`)，每 4 像素压缩为 5 字节。改用 `pBAA` 后，链路校验一次通过。

### 4. 软硬解耦 3A 与软件 ISP 渲染
- **硬件执行**：通过 I2C 向 IMX363 芯片寄存器直接下发物理积分曝光行数（`0x0202`）与模拟放大增益（`0x0204`）。实测模拟增益调至 300 时，物理热噪声方差从 2.77 线性增至 4.38，黑电平基底稳定在原厂 64。
- **软件 ISP**：在 PC 端与应用层使用向量化算法执行 MIPI 5-byte 解包、扣除黑电平 64、BGGR 拜耳滤镜解马赛克与动态范围直方图拉伸，生成 2016×1512 / 4032×3024 全彩图像。

### 5. 旭化成 AK7372 VCM 音圈对焦马达硬件驱动与拓扑打通
- **硬件逆向**：从 MIUI 官方 `vendor.img` 提取的 `com.qti.sensormodule.imx363.bin` 二进制结构体中，破译 polaris 模组（`dipper_imx363_ak7372_semco`）挂载的对焦马达芯片为 **AK7372**（与 AK7375 系列寄存器完全兼容，I2C 7-bit 从机地址 `0x0c`）。
- **供电拓扑**：马达工作电压 2.8V，对应原厂 DTS 中的 `actuator_rear_regulator`，由 SoC TLMM GPIO 26 硬件使能。
- **驱动扩展与拓扑绑定**：
  - 在内核 `drivers/media/i2c/ak7375.c` 中扩展匹配 `"asahi-kasei,ak7372"`。
  - 在 DTS 的 `&cci_i2c0` 下注册 `actuator: actuator@c` 节点，并于 `camera@1a` (IMX363) 下显式声明 `lens-focus = <&actuator>;`。
- **拓扑注册与验证**：构建 `r24` / `#25` 内核后，成功在媒体子系统中生成实体 `entity 237: ak7375 16-000c (subtype Lens)`，对应硬件控制节点 `/dev/v4l-subdev20`，支持 V4L2 `focus_absolute`（0~4095 DAC 步进）。

## 三、 实操验证与使用方法

### 1. 手机端一键拍照与捕获
系统内已持久化固化以下脚本（`/usr/local/bin/`）：
```bash
# 1. 初始化链路拓扑与格式
polaris-cam-setup

# 2. 捕获单帧（自动跳过前5帧使感光积分稳定）
polaris-cam-shoot
```

### 2. 手机端音圈马达硬件调焦 (`polaris-focus`)
系统内固化 `/usr/local/bin/polaris-focus` 脚本，可直接调节镜头对焦物理距离：
```bash
polaris-focus inf      # 无限远/风景远景 (DAC = 0)
polaris-focus mid      # 中景 1~2 米 (DAC = 1500)
polaris-focus close    # 近景 30~50 厘米 (DAC = 2500)
polaris-focus macro    # 极限微距 5~10 厘米 (DAC = 3500)
polaris-focus 2000     # 任意指定 DAC 步进值 (0 ~ 4095)
```

### 3. PC 端一键拍照与调焦工具 (`take_photo.py`)
在 `pmOS-polaris刷机包/03-工具脚本/` 下运行：
```powershell
# 默认拍摄
python take_photo.py

# 指定调焦位置并拍摄（例如极限微距）
python take_photo.py --focus macro
python take_photo.py --focus 3200
```
自动完成：**设置 VCM 对焦 DAC $\rightarrow$ SSH 触发曝光 $\rightarrow$ SCP 拉取 15.24MB RAW 帧 $\rightarrow$ 软件 ISP 矩阵计算 $\rightarrow$ 渲染并输出 `shot.png`**。

### 4. 视频流与预览实测
用户实机测试取景器与视频录制，画面流畅，MIPI 4 通道 636MHz DDR 时钟与 CAMSS DMA 吞吐稳定无压力。

---

### 5. 主线移动生态相机栈原生接入（libcamera + GPU SoftISP + 软件 3A）
为了让桌面级标准应用（如 GNOME Snapshot 快照、PipeWire `pipewire-spa-libcamera`、Megapixels、GStreamer `libcamerasrc`）能够原生接管 IMX363 主摄，我们完成了用户态相机栈的深度打通：
1. **IMX363 传感器元数据与辅助计算接入**：
   - 为 `libcamera` 编写了补丁 `0009-libcamera-Add-Sony-IMX363-sensor-properties-and-helper.patch`。
   - 实现 `CameraSensorHelperImx363`，根据索尼 IMX363 硬件设计绑定原生线性模拟增益计算模型：$$\text{gain} = \frac{512}{512 - \text{code}}$$
   - 注入 IMX363 像素阵列物理尺寸（1.4μm 像元 `1400x1400`）、旋转方向与黑电平基准（`blackLevel = 4096`），彻底消除了 `No static properties available` 与 `Failed to create camera sensor helper` 警告。
2. **高通 Adreno 630 GPU 硬件加速 Debayer**：
   - 启用 `debayer_egl`，利用 Mesa 26.2.4 (OpenGL ES 3.2 / `FD630`) 着色器进行实时硬件去马赛克渲染，实测 **30.33 FPS 稳定满帧运行**（单帧耗时仅约 25ms）。
3. **闭环软件 3A 自适应曝光与白平衡（AEC / AWB）**：
   - IPASoft 根据帧直方图自动收敛曝光时间（4 ~ 3126 行）与模拟增益（1.0x ~ 16.0x），无需人工干预即可在不同光照场景下自适应测光。
