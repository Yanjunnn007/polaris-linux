## 一、 阶段里程碑概览

在经历了第一阶段（屏幕/GPU/基础网络）、第二阶段（USB-SSH 与音频受阻诊断）、第三阶段（Type-C OTG 双角色自动盲插与 5V 升压供电）以及第四阶段（索尼 IMX363 后置主摄 4032×3024 全分辨率出图与硬件调焦）之后，**外放扬声器**成为了 polaris 移植主线 Linux 路上最顽固的“历史遗留钉子户”。

在第二阶段初期，曾一度判定为“高通 SDM845 i2c5 GENI QUP GPI DMA 控制器硬件故障（-EIO），无法与音频芯片通信”。

在第五阶段攻坚中，我们**彻底破译了硬件拓扑、纠正了芯片选型与复位 GPIO、唤醒了 Hexagon ADSP 音频协处理器、修复了 ALSA CPU DAI 拓扑解析错误并完成了用户态 UCM2 适配**，实现了：
1. **真实硬件 100% 破译与通信零误码**：确认为德州仪器 **TAS2559**（`@0x4c`，复位 GPIO 14，负责听筒）与 **TAS2560**（`@0x4d`，复位 GPIO 25，负责底部扬声器）双功放架构；成功下发 3,903 条程序指令 + 1,049 条系数配置，载入 96,514 字节 DSP 固件；
2. **高通 Hexagon ADSP 与 QDSP6 路由全线唤醒**：加载 `adsp.mbn`（13.5MB），APR/GPR 音频服务全面注册；
3. **修复 ALSA DAI Link 拓扑中断**：补充 `&q6asmdai`、`&q6afedai` 与 `&q6voicedai` 子节点，修复 `MultiMedia4: error getting cpu dai name (-22)`；
4. **生成标准 ALSA 声卡**：成功注册 **`card 0: X2S [Xiaomi Mi MIX 2S]`**（包含 MultiMedia1~4 及 VoiceMMode1 共 5 个 PCM 前端）；
5. **打通 ALSA UCM2 与 PulseAudio**：软链接映射 beryllium 经过验证的 UCM 拓扑，PulseAudio 自动枚举扬声器通道 `Voice_Call__Speaker__sink`，实测 `speaker-test`、`aplay`、`paplay` 物理外放发声清晰洪亮。

## 二、 核心攻坚战报与技术破局

### 1. 彻底推翻“GPI DMA 控制器损坏”假说
- **历史困局**：旧驱动假设为单颗 TAS2557，挂在 `i2c5`，复位脚配置为 GPIO 76。开机时报：
  ```text
  geni_i2c 894000.i2c: GPI transfer failed: -5
  tas2557: probe of 5-004c failed with error -5 (-EIO)
  ```
- **逆向破局**：
  - 解包提取小米官方出厂底包全部 14 个 `polaris` 原厂 DTB，通过 Python FDT 解析器进行反编译审计；
  - 发现硬件真相：
    1. 功放芯片根本不是 TAS2557，而是 **TAS2559** 与 **TAS2560** 两颗；
    2. TAS2559 的物理硬件复位脚是 **TLMM GPIO 14**（非 76）；
    3. TAS2560 的物理硬件复位脚是 **TLMM GPIO 25**。
  - **-EIO 真凶定位**：此前驱动拿未连接的 GPIO 76 去拉复位，功放芯片处于完全断电休眠状态。I2C 发送从机地址时无芯片拉低 SDA 应答（NACK），底层 GPI DMA 传输超市超时报 `-EIO`。**不是硬件损坏，是芯片根本没被唤醒！**

### 2. 双芯片协同架构与 0x4d 唤醒
- 内核 `sound/soc/codecs/tas2559.c` 是一个**双芯片协同驱动**（同时管理 `0x4c` 和 `0x4d`），probe 时会同时向两个地址发送广播校验。
- 在 DTS 中同时声明 `ti,tas2559-reset-gpio = <&tlmm 14 0>;` 和 `ti,tas2560-reset-gpio = <&tlmm 25 0>;` 后，两颗芯片全部从休眠中被拉起，I2C 握手与 DSP 固件加载一次通过：
  ```text
  [ 6.756361] tas2559 5-004c: FW Size   = 96514
  [ 6.756367] tas2559 5-004c: Checksum  = 0xD2C6EE29
  [ 6.789606] tas2559 5-004c: tas2559_load_block: Type = 1, commands = 3903
  [ 8.323809] tas2559 5-004c: tas2559_load_block: Type = 3, commands = 1049
  ```

### 3. Hexagon ADSP 固件加载与 QDSP6 路由上线
- SDM845 的音频处理完全托管在高通 Hexagon DSP（QDSP6）上运行。主线设备树默认 `&adsp_pas` 为 `disabled`。
- 在 polaris DTS 中显式启用 `&adsp_pas` 并指定固件路径 `qcom/sdm845/Xiaomi/polaris/adsp.mbn`：
  ```text
  [ 6.692165] remoteproc remoteproc0: Booting fw image qcom/sdm845/Xiaomi/polaris/adsp.mbn, size 13533276
  [ 6.937875] remoteproc remoteproc0: remote processor adsp is now up
  [ 7.055367] qcom,apr remoteproc-adsp:glink-edge.apr_audio_svc.-1.-1: Adding APR/GPR dev: aprsvc:service:4:3
  ```

### 4. 修复 ALSA CPU DAI 拓扑解析错误（MultiMedia4 -22）
- **现象**：ADSP 起来后，`&sound` 机器声卡仍然探测失败，报：
  ```text
  qcom-sound sound: MultiMedia4: error getting cpu dai name: -22
  qcom-sound: probe of sound failed with error -22 (-EINVAL)
  ```
- **破局**：在 DTS 中为 `&q6asmdai`、`&q6afedai` 和 `&q6voicedai` 补全具体的子 DAI 节点：
  ```dts
  &q6afedai {
      dai@22 {
          reg = <QUATERNARY_MI2S_RX>;
          qcom,sd-lines = <0>;
      };
  };

  &q6asmdai {
      dai@0 { reg = <MSM_FRONTEND_DAI_MULTIMEDIA1>; };
      dai@1 { reg = <MSM_FRONTEND_DAI_MULTIMEDIA2>; };
      dai@2 { reg = <MSM_FRONTEND_DAI_MULTIMEDIA3>; };
      dai@3 { reg = <MSM_FRONTEND_DAI_MULTIMEDIA4>; };
  };

  &q6voicedai {
      dai@1 { reg = <1>; /* VOICEMMODE1 */ };
  };
  ```
  重新编译内核后，机器驱动成功获取全部 DAI 名称，声卡一次性注册成功：
  `card 0: X2S [Xiaomi Mi MIX 2S]`。

### 5. 用户态 ALSA UCM2 拓扑适配与自动发声
- polaris 与 Poco F1（beryllium）的音频架构一致，在 `/usr/share/alsa/ucm2/conf.d/sdm845/` 下建立符号链接：
  `Xiaomi Mi MIX 2S.conf -> ../../Xiaomi/beryllium/beryllium.conf`
- 声卡被 PulseAudio 正确接管，生成扬声器 Sink：`alsa_output.platform-sound.Voice_Call__Speaker__sink`。
- 将硬件 Mixer 开关 `QUAT_MI2S_RX Audio Mixer MultiMedia1` 置为 `on`，TAS2559/TAS2560 增益置为 `15`，底层物理音频链路瞬间打通！

## 三、 硬件拓扑与音频数据流全景图

```
[ 用户态应用程序 (浏览器 / 音乐播放器 / 终端) ]
                     ↓
[ PulseAudio 音频服务 (默认 Sink: Voice_Call__Speaker__sink) ]
                     ↓
[ ALSA PCM 接口: /dev/snd/pcmC0D0p (MultiMedia1 前端) ]
                     ↓
[ Linux 内核 q6asm 驱动 (QDSP6 Audio Stream Manager) ]
                     ↓ (高通 GLINK 共享内存协议总线)
[ Qualcomm Hexagon ADSP (运行 adsp.mbn 音频固件) ]
                     ↓ (APR 路由开关: QUAT_MI2S_RX Mixer)
[ Linux 内核 q6afe 驱动 (QDSP6 Audio Front End) ]
                     ↓ (QUATERNARY_MI2S 数据总线)
+──────────────────────────────────────────────────────────+
│ 德州仪器 TI Smart PA 音频子系统 (I2C5 @ 0x894000)         │
│                                                          │
│  [ TAS2559 @ 0x4c ] (GPIO 14 复位)  →  顶置听筒 Earpiece  │
│  [ TAS2560 @ 0x4d ] (GPIO 25 复位)  →  底部主扬声器 Spkr  │
+──────────────────────────────────────────────────────────+
                     ↓
             [ 物理发声：清晰洪亮 ]
```
