## 三、刷机流程总览

```
1. 备份 24 个分区（TWRP dd）—— 救砖保障
2. WSL 装 pmbootstrap
3. 配置 polaris + 打 3 个内核补丁 + 修固件路径
4. pmbootstrap 构建 boot.img + rootfs
5. TWRP 里 dd 把 rootfs 写入 userdata (sda21)
   ※ 不能用 fastboot flash！会写坏 GPT（见坑#3）
6. fastboot 刷 boot.img → 重启 → 进 Phosh
```

## 步骤 1：备份关键分区

> 目的：万一刷坏，能从备份救回。polaris 是单槽设计（boot/system/vendor 单份），刷坏 boot 会变砖。

1. 手机关机，**音量下 + 电源** 进 fastboot
2. 临时启动 TWRP（不刷入，只内存运行）：
   ```
   fastboot boot twrp-3.7.0_9-0-polaris.img
   ```
3. TWRP 起来后 USB 连电脑，adb 应显示 `xxxx recovery`
4. 备份所有分区到手机存储再拉回电脑（脚本见 `03-工具脚本/`，核心命令）：
   ```sh
   # TWRP adb shell 里
   for p in boot system vendor persist modem modemst1 modemst2 devinfo xbl_a xbl_b dtbo; do
     dd if=/dev/block/bootdevice/by-name/$p of=/sdcard/polaris_backup/$p.img bs=4096
   done
   ```
   然后 `adb pull /sdcard/polaris_backup/ .`

> **注意 adb pull 中文路径 bug**：如果电脑目标路径含中文，adb pull 会把目录名截成 8.3 短文件名（如 `polaris_backup` → `polaris_`）。解决：先 pull 到纯英文短路径（如 `E:\pbak`）再移回来。

## 步骤 2：准备 pmbootstrap 环境

pmbootstrap 是 postmarketOS 的官方构建工具。

```bash
# WSL2 Ubuntu 里
sudo apt update && sudo apt install git python3 kpartx android-tools-fsutils

# 注意：PyPI 上的 pmbootstrap 对 Python 3.13/3.14 可能没有匹配版本，
# 直接用源码跑最稳：
git clone https://gitlab.postmarketos.org/postmarketOS/pmbootstrap.git
cd pmbootstrap

# 克隆 pmaports（设备/软件包定义），注意必须用官方 URL 且 main 分支
git clone https://gitlab.postmarketos.org/postmarketOS/pmaports.git ~/pmaports-official
```

初始化配置（会交互提问，也可预先写配置文件）：
```bash
python3 pmbootstrap.py -p ~/pmaports-official init
# 关键选择：
#   Channel: edge
#   Device: xiaomi-polaris
#   UI: phosh            ← polaris 唯一专门适配过的界面
#   service_manager: openrc   ← 我们用 openrc（systemd 当时有别的坑）
```

配置文件位于 `~/.config/pmbootstrap_v3.cfg`，关键项：
```ini
aports = /home/www/pmaports-official
device = xiaomi-polaris
ui = phosh
service_manager = openrc
auto_zap_misconfigured_chroots = yes
```

> **网络问题**：构建要从 postmarketos.org / alpinelinux.org 下载包，国内可能频繁 `Connection aborted`。
> - 办法 1：对断掉的包用 `curl -C - --retry 10 --retry-all-errors` 手动续传到缓存
> - 办法 2：apk 缓存文件命名是 `包名-版本.8位hash.apk`，下好的完整文件要覆盖到对应 hash 文件名
> - 阿里云镜像**没有** pmaports 二进制（只有源码快照），换源走不通，只能硬扛或加速

## 步骤 3：配置 polaris 并打内核补丁

这是核心。polaris 的内核和 initramfs 有四个 bug 需要修（根因见第四节）。补丁在 `02-内核补丁/`。

### 3.1 内核补丁（坑 #1 #2）

把两个补丁放进内核包目录：
```bash
cd ~/pmaports-official/device/community/linux-postmarketos-qcom-sdm845/
cp dsi-10nm-pll-digtop.patch ./
cp panel-nt35596s-prepare-prev-first.patch ./
```

编辑 `APKBUILD`，在 `source=` 列表里加这两行（`default_prepare` 会自动应用所有 `.patch`）：
```
	dsi-10nm-pll-digtop.patch
	panel-nt35596s-prepare-prev-first.patch
```
并把 `pkgrel` 加 1（强制重新构建，避免用缓存）。然后更新校验：
```bash
python3 pmbootstrap.py -p ~/pmaports-official checksum linux-postmarketos-qcom-sdm845
```

### 3.2 initramfs 挂载修复（坑 #3，可选但建议）

> 说明：坑 #3 的主因其实是 **UUID 不匹配**（见第四节），但 blkid 缓存刷新能避免一类时序问题，建议加上。

编辑 `~/pmaports-official/main/postmarketos-initramfs/init_functions.sh`，在 `mount_subpartitions()` 函数里，找到：
```sh
				# Ensure that this was the *correct* subpartition
				# Some devices have mmc partitions that appear to have
				# subpartitions, but aren't our subpartition.
				find_root_partition
```
在 `find_root_partition` 前插入一行：
```sh
				blkid >/dev/null 2>&1 || true
```
然后 `pkgrel` 加 1，`checksum postmarketos-initramfs`。

### 3.3 GPU 固件路径修复（坑 #4）

编辑 `~/pmaports-official/device/archived/firmware-xiaomi-polaris/APKBUILD`，在 `package()` 的 for 循环结束后加：
```sh
	install -Dm644 "$srcdir/$pkgname-$_version/lib/firmware/qcom/sdm845/polaris/a630_zap.mbn" \
		"$pkgdir/lib/firmware/qcom/sdm845/Xiaomi/polaris/a630_zap.mbn"
```
同时编辑同目录 `30-gpu-firmware.files`，追加一行：
```
/lib/firmware/qcom/sdm845/Xiaomi/polaris/a630_zap.mbn
```
`pkgrel` 加 1，`checksum firmware-xiaomi-polaris`。

## 步骤 4：构建镜像

```bash
cd ~/pmbootstrap

# 构建内核（含两个补丁，约 30 分钟，之后有 ccache 会快很多）
python3 pmbootstrap.py -p ~/pmaports-official build linux-postmarketos-qcom-sdm845 --force

# 构建 initramfs 和固件包（aarch64）
python3 pmbootstrap.py -p ~/pmaports-official build postmarketos-initramfs --force --arch=aarch64
python3 pmbootstrap.py -p ~/pmaports-official build firmware-xiaomi-polaris --force --arch=aarch64

# 生成完整镜像（设置登录密码）
python3 pmbootstrap.py -p ~/pmaports-official -y install --password 你的密码
```

产物：
- boot.img：`~/.local/var/pmbootstrap/chroot_rootfs_xiaomi-polaris/boot/boot.img`
- rootfs（sparse）：`~/.local/var/pmbootstrap/chroot_native/home/pmos/rootfs/xiaomi-polaris.img`

**关键检查（避免坑 #3 的 UUID 不匹配）**：每次 `install` 都会重新生成 rootfs 的 UUID，所以 **boot.img 和 rootfs 必须是同一批 install 出来的，一起刷**。验证：
```bash
strings .../boot.img | grep -oE 'pmos_(root|boot)_uuid=[a-f0-9-]+'
# 与 rootfs 解包后的子分区 UUID 对比，必须一致
```

rootfs 是 Android sparse 格式，dd 前要转 raw：
```bash
simg2img xiaomi-polaris.img pm-raw.img
```

## 步骤 5：刷入 rootfs（TWRP dd 法）

> ⚠️ **绝对不能用 `fastboot flash userdata`**！见坑 #3：fastboot 的 sparse 写入会把 4096 扇区镜像的 GPT 分区条目区写坏，导致 initramfs 找不到子分区。必须用 TWRP 的 dd 逐字节写。

1. 手机进 fastboot（音量下+电源）
2. 临时启动 TWRP：`fastboot boot twrp-3.7.0_9-0-polaris.img`
3. 等 adb 显示 `recovery`，推 rootfs 直接写入 userdata 块设备（polaris userdata = `/dev/block/sda21`）：
   ```
   adb push pm-raw.img /dev/block/sda21
   ```
   3.4GB 约 100 秒（约 33MB/s）。
4. **验证 GPT 写对了**（关键，脚本见 `03-工具脚本/twrp_gpt.sh`）：
   - GPT 头签名应为 `EFI PART`
   - 条目 1/2 的 unique GUID 应与镜像内 PARTUUID 一致

> polaris 分区速查：`userdata=/dev/block/sda21`（57GB）、`boot=/dev/block/sde45`、`system=sde48`（重启后可能变 sdf48）、`persist=sda14`、`modem=sde46`。

## 步骤 6：刷入 boot.img 并启动

1. TWRP 里 `adb reboot bootloader` 回 fastboot
2. 刷 boot：
   ```
   fastboot flash boot boot-fixed3.img
   fastboot reboot
   ```
3. **观察屏幕**：
   - 解锁警告屏（几秒）
   - **pmOS 启动画面**（Plymouth splash）——证明屏幕点亮
   - **Phosh 锁屏**——证明全部成功
4. 解锁：上滑，输入密码（构建时设的那个）。

## 四、四大坑的根因与修复

这一节是本次移植最有价值的技术记录。polaris 在 pmOS 上"黑屏、起不来"其实不是一个 bug，而是四个叠加的问题。

### 坑 #1：DSI PHY PLL 锁不上（屏幕黑屏原因之一）

- **dmesg 症状**：
  ```
  msm_dsi_phy ae94400.phy: [drm:dsi_pll_10nm_vco_prepare] *ERROR* DSI PLL(0) lock failed, status=0x00000000
  ```
- **根因**：`drivers/gpu/drm/msm/dsi/phy/dsi_phy_10nm.c` 的 `dsi_pll_enable_pll_bias()` 只给 `CMN_CTRL_0` 置了 BIT(5)（PLL bias），**漏了 BIT(6)（digital top 上电）**。内核 7.1 的 clk 框架会在 probe 阶段提前 enable PLL（qcom dispcc 的 assigned-clock-parents 改动引入），此时 PHY digital top 还没上电 → VCO 起不来 → 状态寄存器读全 0 → lock 失败。
- **性质**：这是**内核 7.1 的通用回归**，不是 polaris 专有。上游 Dmitry Baryshkov 2026-09-24 为 7nm PHY 发了同款修复（报错一字不差），Luca Weiss 确认 10nm 是同一个 bug 并已移植修复但未发出。
- **修复**：`02-内核补丁/dsi-10nm-pll-digtop.patch`——把 pll_bias 的置位/清位从 `BIT(5)` 改成 `BIT(6)|BIT(5)`。

### 坑 #2：面板 DCS 初始化被拒 -22（屏幕黑屏原因之二）

- **dmesg 症状**：
  ```
  panel-jdi-nt35596s ae94000.dsi.0: failed to send DCS Init 1st Code: -22
  ```
- **根因**：polaris 面板是 JDI FHD + Novatek NT35596S（DSI video mode）。面板驱动需要在 `prepare()` 回调里发 DCS 初始化命令，但 DRM bridge chain 默认把 panel 的 `prepare()` 排在 DSI host 的 power_on **之前**执行。于是第一条 `mipi_dsi_dcs_write` 走到 `dsi_host_transfer()` 时 `msm_host->power_on == false`，直接返回 `-EINVAL (-22)`。
- **修复**：`02-内核补丁/panel-nt35596s-prepare-prev-first.patch`——在 `nt35596s_panel_add()` 里加一行 `pinfo->base.prepare_prev_first = true;`，把 panel prepare 排到 pre_enable 链末尾（host power_on 之后）。
- **背景**：这本是 Icenowy Zheng 2024-02 提交的修复（sdm845-mainline MR !85 的 commit `2c875e90`），同系列的 Caleb Connolly `5ab33e94` 给其他 SDM845 面板（sofef00/s6e3fc2x01/nt36672a/ft8719）都加了这个 flag，**唯独漏了 nt35596s**（因为该驱动是后加的）。MR !85 至今**没合进 7.1 分支**——这就是 polaris 显示长期 Partial 的直接原因。

### 坑 #3：rootfs 自动挂载失败（系统起不来）

- **initramfs 日志症状**：
  ```
  Mount subpartitions of /dev/sda21  (×5~6)
  ERROR: failed to mount subpartitions!
  ```
- **根因 A（数据层）**：fastboot 的 sparse 写入 bug。polaris 的 deviceinfo 指定 `deviceinfo_rootfs_image_sector_size="4096"`，rootfs 镜像的 GPT 按 4096 扇区布局。fastboot（Windows/Linux 都一样）把这种 4096 扇区 sparse 镜像刷到 512 扇区的 userdata 时，**GPT 主头写对了，但分区条目区（LBA2-33）写成乱码** → initramfs 找不到 pmOS_root/pmOS_boot 子分区。**修复**：TWRP dd 逐字节写（步骤 5）。
- **根因 B（UUID 不匹配，我们实际踩的）**：`pmbootstrap install` 每次都会重新生成 rootfs 的 ext4 UUID，并写进 boot.img 的内核命令行 `pmos_root_uuid=...`。initramfs 的 `find_partition()` 一旦拿到 UUID 就**只按 UUID 找，找不到直接返回，绝不回退 label**。所以新 boot.img + 旧 rootfs = 永远找不到。**修复**：boot.img 和 rootfs 必须同一批 install、一起刷。
- **根因 C（blkid 缓存，建议性修复）**：util-linux 的 `blkid --uuid` 只读 `/run/blkid/blkid.tab` 缓存、不重新探测新建设备。`mount_subpartitions()` 用 losetup 建 loop 后直接 `blkid --uuid`，新建的 loop0p1/p2 不在缓存里会漏。我们手动成功正是因为手动跑过 `blkid` 刷新了缓存。**修复**：losetup 后加一行 `blkid`（见步骤 3.2）。

### 坑 #4：GPU 渲染器起不来（Phosh 卡在终端/EGL 错误）

- **屏幕症状**：系统能进 Phosh，但满屏 `phoc/wlroots` 错误：`Could not initialize EGL`、`Could not initialize renderer`、`Failed to create server: Could not create renderer`。
- **dmesg 症状**：
  ```
  adreno 5000000.gpu: [drm:adreno_zap_shader_load] *ERROR* Unable to load qcom/sdm845/Xiaomi/polaris/a630_zap.mbn
  msm_dpu ae01000.display-controller: [drm:adreno_load_gpu] *ERROR* gpu hw init failed: -2
  ```
- **根因**：Adreno 630 的 zap shader 是 GPU 上电初始化的**必经步骤**（把 GPU 从安全态切到普通态），加载失败 → GPU probe `-ENOENT` 完全失败 → DRM render node 没注册 → phoc/wlroots 找不到 GPU → EGL/renderer 起不来。
  路径不匹配的由来：2025-12-22 David Heidelberg 的 patch 把 polaris dts 里 `gpu_zap_shader` 的 `firmware-name` 从 `qcom/sdm845/polaris/a630_zap.mbn` 改成 `qcom/sdm845/Xiaomi/polaris/a630_zap.mbn`（统一成 `qcom/sdm845/<Vendor>/<codename>/` 格式，配合 droid-juicer 从 vendor 分区提固件）。但 linux-firmware 上游从没提供过带 `Xiaomi/` 子目录的版本，pmOS 的 `firmware-xiaomi-polaris` 包也还在用旧路径。
- **修复**：见步骤 3.3——把 `a630_zap.mbn` 同时安装到 `qcom/sdm845/Xiaomi/polaris/` 路径（用户态对齐新旧路径，正是上游推荐的过渡方式）。

## 五、常见问题 FAQ

> 第二阶段（WiFi/蓝牙/SSH/音频）的详细记录见 [第七节](#七第二阶段wifi--蓝牙--usb-ssh-通道--音频现状)，在 FAQ 之后。

**Q1：fastboot devices 没输出 / 时有时无？**
A：usbipd 残留绑定占用（如果之前用 usbipd 把 USB 透给 WSL）。`usbipd unbind` + 拔插 USB + `pnputil /remove-device` 重新枚举。另外 fastboot 界面几秒不操作会自动尝试启动，要按音量键锁定在 fastboot。

**Q2：adb 显示 unauthorized？**
A：手机屏幕上点 USB 调试授权。注意别混淆多台设备——我们 polaris 序列号是 `3ea12cce`（如果电脑还连着别的安卓设备，用 `adb -s 3ea12cce ...` 指定）。

**Q3：系统 prop 显示 `flash.locked=1`，是不是 BL 没解锁？**
A：那是误导。权威看 fastboot `oem device-info`：`Device unlocked: true` + `Device critical unlocked: true` 才是真解锁。

**Q4：屏幕亮了但只有背光没图像？**
A：那是坑 #1/#2 没修好（PLL 或 DCS）。查 dmesg 的 `lock failed` 和 `DCS Init`。

**Q5：串口 COM5 打不开 / 无输出？**
A：pmOS 串口 console 要等系统起来才激活；启动早期 Windows 端设备可能显示 Unknown。多用回车唤醒。串口回显常不可靠（只回命令本身），看 PMOS_LOGS 盘的 `dmesg.txt` 更靠谱。

**Q6：PMOS_LOGS 盘是干嘛的？**
A：initramfs 挂载**失败**时会自动格式出一个 32MB 的 FAT 盘（卷标 PMOS_LOGS），里面有 `dmesg.txt`、`blkid.txt`、`pmOS_init.txt` 等，是调试启动问题的金矿。挂载**成功**则不出现。

**Q7：刷完想回 MIUI 怎么办？**
A：用步骤 1 的备份：fastboot 刷回 `boot.img`（必要时 system），`fastboot reboot`。

## 七、第二阶段：WiFi / 蓝牙 / USB-SSH 通道 / 音频现状

> 第一阶段（屏幕/系统/GPU）打通后的后续修复，2026-10-08 整理。
> 这几个问题有一个共同根因模式：**dts 把固件路径写成了 `.../Xiaomi/polaris/`，但固件包只装到了不带 `Xiaomi/` 的旧路径**——和坑 #4 完全同源。

### 7.1 WiFi 修复（WCN3998 / ath10k）

- **症状**：`ip link` 没有 `wlan0`，`lsmod` 里 ath10k 全加载但 dmesg 无 ath10k 输出。
- **根因有两层**：
  1. dts `&wifi` 节点缺 `qcom,snoc-host-cap-skip-quirk`（Icenowy MR !85 commit `3e6b21a7`）——补上后 modprobe 能成功但仍无网卡。
  2. **主因**：WCN3998 通过 remoteproc/QMI 挂在 modem 子系统上，而 modem 固件 `mba.mbn` 也走 `qcom/sdm845/Xiaomi/polaris/` 路径 → `Direct firmware load for qcom/sdm845/Xiaomi/polaris/mba.mbn failed with error -2`。modem 起不来，挂在它上面的 WiFi 自然不会注册。
- **修复**：把 15 个 modem/remoteproc 固件（`mba.mbn modem.mbn modemr.jsn modemuw.jsn wlanmdsp.mbn adsp.mbn adspr.jsn adspua.jsn cdsp.mbn cdspr.jsn ipa_fws.mbn slpi.mbn slpir.jsn slpius.jsn venus.mbn`）安装到 `qcom/sdm845/Xiaomi/polaris/` 路径（同坑 #4 的做法，已写进 `firmware-xiaomi-polaris/APKBUILD`）+ 内核补丁 `dts-wifi-snoc-skip-quirk.patch`。
- **实测**：能搜到 WiFi、连校园网、火狐看 B 站视频流畅。

### 7.2 蓝牙修复（WCN3998 / hci_uart_qca）

- **症状**：Phosh 控制中心蓝牙开关打开瞬间弹回，`hciconfig` 显示 `BD Address: 00:00:00:00:5A:AD`（全零假地址）。
- **根因**：又是同一个固件路径坑。蓝牙是串口设备（`serial0-0`，驱动 `hci_uart_qca`），dts 里写 `firmware-name = "Xiaomi/polaris/crnv21.bin"`（相对 `qca/`），内核先加载 rampatch `qca/crbtfw21.tlv`（能找到），再加载 NVM `qca/Xiaomi/polaris/crnv21.bin`（找不到，-2）→ MAC 地址没注入 → 系统发现蓝牙无地址立刻关开关。
  ```
  Bluetooth: hci0: QCA Downloading qca/Xiaomi/polaris/crnv21.bin
  bluetooth hci0: Direct firmware load for qca/Xiaomi/polaris/crnv21.bin failed with error -2
  ```
- **修复**（已固化进固件包 pkgrel=3）：把 NVM 装到 `qca/Xiaomi/polaris/` 路径。APKBUILD 里加：
  ```sh
  	install -Dm644 "$srcdir/$pkgname-$_version/lib/firmware/qca/polaris/crnv21.bin" \
  		"$pkgdir/lib/firmware/qca/Xiaomi/polaris/crnv21.bin"
  ```
- **不刷机临时生效**（如果已刷好不想重刷）：手机上手动建链接再重绑驱动：
  ```sh
  sudo mkdir -p /lib/firmware/qca/Xiaomi/polaris
  sudo ln -sf /lib/firmware/qca/polaris/crnv21.bin /lib/firmware/qca/Xiaomi/polaris/crnv21.bin
  echo serial0-0 | sudo tee /sys/bus/serial/drivers/hci_uart_qca/unbind
  sleep 2
  echo serial0-0 | sudo tee /sys/bus/serial/drivers/hci_uart_qca/bind
  # 验证：dmesg 应出现 "QCA setup on UART is completed"，hciconfig 显示真 MAC
  ```
- **实测**：`BD Address: AA:BB:CC:DD:EE:FF`（真地址），`UP RUNNING`，开关不再弹回。

### 7.3 USB-SSH 通道（调试用，以后不用手机拍照传日志了）

- **背景**：pmOS 默认 USB 网卡用 **NCM 模式**（`ncm.usb0`），但 **Windows 没有 NCM 驱动**（设备管理器显示 `CDC NCM` 报错）→ USB 插电脑没法 SSH。微软其实自带 `UsbNcm.sys`，只是 INF 没绑到手机的 `VID_18D1&PID_D001`。
- **解决**（纯 Windows 侧，不动手机）：
  1. 从 `C:\Windows\System32\DriverStore\FileRepository\usbncm.inf_amd64_*\` 抠出 `UsbNcm.sys`。
  2. 写个 `pmos_ncm.inf`，把 `UsbNcm_Device` 绑到 `USB\VID_18D1&PID_D001&MI_00`（和 `&REV_0701&MI_00`）。
  3. **关键坑**：Windows 强制要求 INF 配签名 `.cat`，而 `pnputil /add-driver` 对"第三方 INF 无数字签名"直接拒绝（`0xE0000247`）。即便 Secure Boot 关着也一样。解法：
     - `bcdedit /set testsigning on` + `bcdedit /set nointegritychecks on`（Secure Boot 关闭时可用），**重启电脑**激活测试模式（右下角出"测试模式"水印）。
     - 用 `Inf2Cat.exe`（WDK 提取）对**只含 inf+sys 的干净目录**生成 `.cat`（注意：inf2cat 会把目标目录里所有文件当驱动文件，目录里有大文件会失败），再用 `signtool.exe` 拿自签证书签它。
     - `pnputil /add-driver pmos_ncm.inf /install` 即成功（`已成功添加驱动程序程序包 / oem43.inf / 已安装在设备上`）。
  4. 手机变网卡 `以太网X (pmOS NCM Network Adapter)`，配 IP `172.16.42.2/24`，即可 ping 通手机 `172.16.42.1`。
  5. WSL 共享 Windows 网络栈，直接 `ssh user@172.16.42.1`（建议配 ssh 公钥免密 + `sudo NOPASSWD`）。
- **价值**：之后所有调试都能 SSH 进去跑命令，不用手机小屏幕敲命令 + 拍照。
- 完整脚本与 INF 见 `03-工具脚本/windows-ncm-driver/`。

### 7.4 音频现状（未解决，SDM845 公认难点）

- **症状**：`aplay -l` 显示 `no soundcards found`，`rc-service alsa` stopped，看视频无声。
- **诊断结论**：
  - 编解码器其实是 **WCD9340**（高通自家，dts `#include "sdm845-wcd9340.dtsi"` + `&wcd9340` 节点），不是之前以为的 tas2559。
  - ADSP/CDSP remoteproc 都 `running`，内核 `CONFIG_SND_SOC_SDM845=m`、`CONFIG_SND_SOC_WCD9340=m` 等 config 全开，模块 `snd-soc-tas2559`/`snd-soc-wcd9340` 都在。
  - **但 `/proc/device-tree/sound` 节点是空的**（只有 name 没有 compatible）——dts 里**根本没有定义机器级 `sound` 节点**（把 CPU DAI、codec、platform 粘起来的那层"胶水"），所以机器驱动 `snd-soc-sdm845` modprobe 成功也找不到设备注册声卡。
- **修复方向（未做，需重刷内核）**：参考同为 SDM845+WCD9340 的 OnePlus 6（`sdm845-oneplus-common.dtsi` 的 `sound { compatible = "qcom,sdm845-sndcard"; ... }`，含 MultiMedia1-6 + Speaker + SLIM 收放音共 12 个 dai-link），给 polaris dts 补一个 `sound` 节点 → 重编内核 → 重刷 boot。
- **难点提醒**：即便声卡出来，**外放扬声器能不能响**还取决于功放 dai-link——MIX 2S 外放走 tas2559（I2S 智能功放），OnePlus 6 用的是 max98927，模板不直接适用，扬声器路由可能要单独调。SDM845 扬声器在 mainline 至今是多数设备的硬骨头。**建议先用 USB-C 转 3.5mm 或蓝牙音频过渡**。

## 八、第三阶段：Type-C CC 自动盲插与 5V VBUS OTG 双角色完全打通

> **攻坚日期**：2026-10-12
> **交付内核**：`7.1.0-rc1-sdm845`（r20），镜像 `01-刷机镜像/boot-r20.img`
> **最终实测**：100% 打通。无源 USB 2.0 HUB + 2.4G 键盘 + 8K 鼠标盲插即亮、全功能工作；拔掉自动切断 5V 升压；插电脑自动切 Device 恢复 NCM 调试通道。

### 1. 为什么 OTG 搁置了这么久？
在第二阶段，我们排查了尝试使用 `extcon-usb-gpio` + PMIC GPIO8 的方案并实测推翻。
SDM845 平台的 Type-C 物理层（CC1/CC2 逻辑检测、VBUS 升压开关）完全受控于 PMI8998 PMIC 内部的 SMB2 充电子系统。
社区先驱 Casey Connolly 曾在 5.x 内核写过 `qcom-pmi8998-tcpm`，但因未并入主线，在 Linux 7.1 上存在大量 API 断层与运行时逻辑死锁。

### 2. 核心 Bug 深度定位与修复
1. **消抖完成无事件上报死锁（Debounce Notification Loss）**：
   硬件检测到 CC 下拉后进入 10ms 消抖工作队列 `qcom_pmic_typec_port_cc_debounce`，执行完消抖后漏掉了 `tcpm_cc_change()` 调用。TCPM 状态机因此一直卡在 `SRC_UNATTACHED`，永远无法转入 `SRC_ATTACH_WAIT`。
   - **修复**：在消抖函数末尾加上 `if (pmic_typec_port->tcpm_port) tcpm_cc_change(pmic_typec_port->tcpm_port);`。
2. **VBUS 状态追踪异或逻辑 Bug 与安全断电判定死锁（VBUS State Machine Deadlock）**：
   开机时 `pmic_typec_port->vbus_present` 默认为 0。拔下电脑后，异或判断 `curr_vbus ^ vbus_present` 计算为 `0 ^ 0 = 0`，导致系统从未感知到 VBUS 掉电！TCPM 状态机一直认为总线有残留高压，`vbus_vsafe0v` 保持为 `false`。根据 Type-C 国际安全规范，在检测到总线电压非零时严禁开启升压供电，导致 5V boost 被永久安全锁死。
   - **修复**：
     - 改为直接比对真实寄存器状态 `if (curr_vbus != pmic_typec_port->vbus_present)`。
     - 开机 `port_start` 时主动查询当前物理 VBUS 并初始化 `vbus_present`。
     - 重构 `is_vbus_vsafe0v` 逻辑，在硬件无专用比较器时，以 `!pmic_typec_port->vbus_present` 作为安全零伏判定。
3. **DTS 偏好角色引起的握手延时（Try.SNK Race Condition）**：
   移除 DTS 中的 `try-power-role = "sink"`，配置为纯粹对等的双角色 DRP（Symmetric DRP），实现瞬时识别 Source 并输出 5V。
4. **Kernel Lockdown 签名限制与输入驱动内置化**：
   EFI Lockdown 模式拒绝未签名模块加载。我们将 `CONFIG_HID_GENERIC=y` 和 `CONFIG_INPUT_EVDEV=y` 固化为内置（Built-in），并同步更新了 `modules-r20.tar.gz`。

### 3. 实机验证 dmesg 日志节选
- 插入无源 HUB + 键鼠：
  ```

  tcpm-source-psy-4-0013: set_vbus: 1
  ```

- 插回电脑：`dwc3: Mode 2`（从机模式），NCM 网卡与 SSH 恢复。

## 九、第四阶段：索尼 IMX363 后置主摄硬件出图与录像完全打通

### 1. 突破概览
在第三阶段解决 OTG 之后，我们正式攻坚长期被社区列为“Broken / 搁置”的摄像头。此前 Poco F1 的主线相机补丁在 MIX 2S 上完全不工作。我们逆向官方底包二进制 Chromatix 配置，攻克了从机硬件地址差异、重构供电树与 CAMSS RDI 格式链路，于 2026-10-13 实现了 **4032×3024 10-bit Packed Bayer（`pBAA`）全分辨率 RAW 数据捕获、软件 ISP 渲染成图与流畅录像**。

### 2. 四大关键技术突破
1. **逆向破译真实 I2C 从机地址（0x10 $\rightarrow$ 0x1a）**：
   - Poco F1 挂在 `0x10`，MIX 2S 实测通讯超时。
   - 挂载 MIUI 原厂底包 `vendor.raw.img`，深入反编译 Chromatix 相机配置 `com.qti.sensormodule.imx363.bin`，在偏移 `0x1efdc` 查得 Polaris 8-bit 地址为 `0x34` $\rightarrow$ 7-bit 地址为 `0x1a`，芯片 ID `0x0363`。
   - 内核在 `0x1a` 成功识别芯片 ID：`Found IMX363 chip id 0x0363 on addr 0x1a (attempt 0)!`
2. **供电树与 24MHz 时钟编排**：
   - DVDD 1.05V (PM8998 GPIO 11)、AVDD 2.8V (TLMM 87)、IOVDD 1.8V (TLMM 21)、客制 TLMM 102。
   - 在复位保持下按序上电、注入 24MHz CAMCC MCLK 时钟，释放 GPIO 80 高电平复位。
3. **CAMSS RDI 链路与格式匹配（排查 -EPIPE 断管）**：
   - CAMSS CSID 输出 `MEDIA_BUS_FMT_SBGGR10_1X10`，V4L2 必须匹配紧凑打包 MIPI RAW10 格式 `pBAA` (`V4L2_PIX_FMT_SBGGR10P`)，每 4 像素压缩为 5 字节。单帧精确大小：$4032 \times 3024 \times 1.25 = 15,240,960$ 字节。
4. **软硬解耦 3A 与软件 ISP 图像渲染**：
   - 硬件直驱：通过 V4L2 控制器向索尼芯片直写物理电子快门行数（`0x0202`）与模拟放大增益（`0x0204`）。模拟增益拉高至 300 时物理热噪声方差由 2.77 线性增至 4.38，黑电平锁定原厂 64。
   - 软件 ISP：在 PC / 应用层用向量化矩阵运算完成 MIPI 解包、黑电平扣减、拜耳 BGGR 解马赛克与动态范围拉伸，全彩出图。
5. **AK7372 VCM 音圈马达硬件驱动与精准调焦打通**：
   - 逆向破译：从底包 `com.qti.sensormodule.imx363.bin` 中定位 polaris 马达为 `dipper_imx363_ak7372_semco`（AK7372 芯片，与 AK7375 寄存器兼容，I2C 从机地址 `0x0c`，2.8V 独立供电，由 TLMM GPIO 26 使能）。
   - 驱动扩展：在内核 `ak7375.c` 中扩展 `"asahi-kasei,ak7372"` 兼容匹配；在 DTS 的 `&cci_i2c0` 下注册马达并在 IMX363 声明 `lens-focus = <&actuator>;`。
   - 控制实测：系统注册 `/dev/v4l-subdev20`，支持 V4L2 `focus_absolute`（0~4095 步进）。提供手机端 `polaris-focus` 脚本与 PC 端 `take_photo.py --focus <val>`，实测从无限远（0）到极限微距（3500）对焦平滑精准。
6. **libcamera + SoftISP (Adreno 630 GPU 加速) + 软件 3A 原生接入**：
   - 为 libcamera 增加 IMX363 增益模型 $\text{gain} = \frac{512}{512 - \text{code}}$ 与像元元数据补丁。
   - 依托 Mesa 26.2.4 (OpenGL ES 3.2 / `FD630`) GPU 硬件加速着色器进行去马赛克渲染，达成 **30.33 FPS 满帧流式吞吐**。
   - IPASoft 自动收敛测光 AEC（4~3126 行）与白平衡 AWB。

## 十、第五阶段：内置双外放扬声器与听筒 (TAS2559+TAS2560) 完全打通

> **攻坚日期**：2026-10-13  
> **交付内核**：`7.1.0-rc1-sdm845`（r27，构建 #28），镜像 `01-刷机镜像/boot-r27.img`，模块 `modules-r27.tar.gz`  
> **最终实测**：100% 成功。彻底推翻旧版“GPI DMA 硬件死锁”推论；确认为 TI TAS2559 (0x4c) + TAS2560 (0x4d) 双 Smart PA 架构；唤醒 Qualcomm Hexagon ADSP 子系统与 QDSP6 路由；ALSA 机器声卡 `card 0: X2S [Xiaomi Mi MIX 2S]` 完美注册；UCM2 拓扑适配完成；PulseAudio 默认 Sink 与 ALSA 底层外放实测全部清晰发声！

### 1. 突破概览与根因复盘
1. **推翻“硬件控制器损坏”假说**：此前由于使用错误型号（误以为单颗 TAS2557）与错误复位脚（GPIO 76），导致芯片休眠无法响应 I2C，引发总线等待超时报 `-EIO`。通过逆向 MIUI 原厂 DTB 确诊为 **TAS2559 (听筒/主功放, GPIO 14) + TAS2560 (底部外放, GPIO 25)**。改用正确 GPIO 与型号后，DSP 固件（96KB、3903 条指令、1049 条系数）成功下发，I2C 通信零故障！
2. **唤醒 Hexagon ADSP**：激活 `&adsp_pas`，加载 13.5MB `adsp.mbn`，完整启动高通音频 DSP 实时系统，使 GLink APR 路由总线（`aprsvc:service:4:3~4:b`）全量上线。
3. **修复 MultiMedia CPU DAI 缺失**：补齐 DTS 中 `&q6asmdai`（MultiMedia1~4）、`&q6afedai`（QUATERNARY_MI2S_RX line 0）与 `&q6voicedai` 子节点，消除 `MultiMedia4: error getting cpu dai name (-22)` 报错，声卡驱动顺畅 probe。
4. **ALSA UCM2 拓扑与 PulseAudio 无缝绑定**：建立 `Xiaomi Mi MIX 2S.conf` 拓扑链接，重载 UCM HiFi，PulseAudio 自动创建 `Voice_Call__Speaker__sink`，实现系统通知、浏览器、多媒体一键默认外放。
